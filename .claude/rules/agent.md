## The agent (decided)

**Shape: a hybrid graph.** The outer graph is fixed and small, the agent node is a bounded tool loop (`agents/repolace_agents/graph.py`). As built it is `localize -> agent -> verify`, then a conditional edge (`route`) back to `agent` or to the end. The plan's sketch was `localize -> agent -> verify -> decide -> finalize`; `decide` is that conditional edge, and **there is no `finalize` node**: scoring, the PR gate, the squash, the push and the final database write need git, Postgres and GitHub, so they live in the pipeline (`run_task`), after the agent returns an `AgentResult`. `localize` makes no model call; `agent` is the only node that calls the model; `verify` is the only node that reads the oracle, and only to hand it to the feedback filter. State is a frozen dataclass in which **every field has a default** (LangGraph builds it as `schema(**input)`, a fresh instance per node), and dependencies travel in the run context, not the state. The recursion limit is a guard, `4 * max_attempts + 8` (the default is 10007, effectively unlimited), so a routing bug becomes a `GraphRecursionError` within a dozen steps instead of a model call per step until the budget ends it. Phase 1 deliberately keeps **one agent, not split by role**; Phase 2 splits it after seeing where this one overloads.

**The pipeline calls `run_agent`, never `run_graph`.** `run_agent` draws a fresh `secrets.token_hex(8)` delimiter nonce per call and takes no parameter for it, because a nonce a caller can choose is one an attacker can predict. `run_graph` takes the nonce only so a test can fix it.

**Bounds.**

| bound | value | where |
|---|---|---|
| attempts | 3 (`AgentLimits.max_attempts`) | a retry happens only on a *fresh*, not-clean scored attempt, with attempts left and no infrastructure fault |
| steps (model calls) per attempt | 40 | `STEP_CAP` when reached |
| tool calls executed per model reply | 8 (`MAX_TOOL_CALLS_PER_REPLY`); the rest are answered "not executed", never run | the injection audit scripted a single reply of 3,000 calls and all were executed, each `run_python` up to 120 s |
| task cost | $2.00 (`DEFAULT_MAX_USD`) | the gateway, not the agent |
| model calls per task | 150 (`DEFAULT_MAX_CALLS`) | the gateway; 3 attempts x 40 steps is at most 120 |
| wall clock per task | 3600 s (`DEFAULT_MAX_WALL_SECONDS`) | the gateway; **started when the agent stage starts** (`_agent_budget`), not at the task's start, so a clone, an index that waited twenty minutes for another task's lock and a baseline run cannot eat the cap and charge an instrument limit to the agent |

The budget is also checked between tool calls, not only inside the next model call, because a reply's calls can each run for minutes. A budget stop does **not** append the response that crossed the line (its tool calls cannot run, and an assistant message whose `tool_calls` have no answers is rejected by the provider on the next call). `UnpricedModelError`, `MissingProviderKey`, `NoTaskScope` and anything else propagate: they mean repolace is misconfigured, and a task that fails loudly is worth more than one that quietly reports a stop reason. Only the `agent` stage is called in Phase 1; the `cheap` stage is required by the gateway config and unused.

**The nine tools** (`agents/repolace_agents/tools/`), plain async functions with JSON schemas that `ToolBox` **enforces** (`enum`, `minimum`, `maximum`, `minLength`, `maxLength`, `minItems`, `maxItems`, `items.type`; it refuses at construction a schema using a keyword it does not enforce, so a schema never advertises a bound nothing checks). Every result is capped at 8,000 characters. A model-visible failure (`ToolError`) becomes an error result; anything else is repolace's bug and propagates, so a broken tool cannot pass for a model that is bad at using it.

| tool | what it does | bounds |
|---|---|---|
| `search_code` | the index, through an injected callable that opens its **own short-lived session** per call | query 1-500 chars, limit 1-20 (default 8) |
| `read_file` | numbered lines | at most 400 lines a call; files over 1,000,000 bytes refused |
| `grep` | `git grep` over *tracked* files | below |
| `list_dir` | entries to a depth | depth 1-3, at most 300 entries |
| `edit_file` | exact, unique match | `old_string` and `new_string` at most 20,000 chars |
| `create_file` | a new, non-protected file | at most 100,000 chars |
| `run_python` | a scratch script in the sandbox, no network | code at most 20,000 chars, timeout 1-120 s (default 60) |
| `run_tests` | a probe: some visible tests, not scored | at most 20 targets, probe timeout 300 s |
| `submit` | ends the loop | summary 1-4,000 chars, no control characters |

**What bounds them.** Every path goes through one function (`tools/paths.py::confine`, built on `resolve_within`): empty, over-long (500 chars), control-character or backslash paths, `..`, absolute paths and **any symlink anywhere in the path, even one that lands back inside the tree** are refused, because following it would let the repository choose where a later read or write goes. Anything with a component starting `.git` (`.git`, `.gitignore`, `.gitattributes`, `.gitmodules`, `.github`) is refused for reads too, case-folded, with HFS-ignorable code points stripped and the NTFS short name `git~1` refused. For **writes**, additionally, any component starting with `.` is refused (default-deny: `.circleci/`, `.travis.yml`, `.vscode/`, `.devcontainer/`, `.husky/`, `.envrc`, ...), plus root-level CI definitions that are not dotfiles (`Jenkinsfile`, `azure-pipelines.yml`, `appveyor.yml`, `cloudbuild.yaml`, `bitbucket-pipelines.yml`), plus `ToolContext.is_protected`. The dotfile rule replaced a `.git*`-only guard after the security review showed the `.git*` prefix covered `.github` but left a dozen other CI and editor-hook locations writable (see "Known limit" in `.claude/rules/prompt-injection.md` for what a deny list still cannot cover). `grep`'s argument vector is built to one rule: **a model-supplied string is never placed before `--` and is never an option**: the pattern is the operand of `-e`, the path follows `--`, and `--literal-pathspecs` stops git reading the path as pathspec magic or a tree-ish. `-E` is glibc's regex engine, which is not safe against a hostile pattern (a 28-character nested counted repetition was measured at about 5 GB resident), so the child runs **resource-limited**: `prlimit --as=512MiB --cpu=15:20 -- git ...`, `--threads=1`, a 20 s wall clock, output read back to at most 1 MiB, the whole process group killed on timeout, and patterns with a backreference or a counted repetition bound of 100 or more are refused up front. `prlimit` is a host dependency (see "Deployment requirements for the sandbox host" in `CLAUDE.md`). `run_tests` targets must match a safe path pattern whose first character is never `-` (an option) or `@` (pytest expands `@file` into arguments), must name a file that exists and passes the read guard, and are normalised before use (`./-x` would otherwise become the option `-x`). **No new test files:** see "Decided since" under the success criteria.

**Retries and feedback.** After `submit` (or a step cap) the pipeline scores the attempt; if the feedback filter finds visible regressions or collection errors and attempts remain, the model gets one message and another attempt, with earlier tool outputs replaced by `[output from attempt N elided]` (the assistant messages and their `tool_calls` stay, so every call still has an answer and the transcript stays valid). A transcript over 400,000 characters has its older tool results elided mid-attempt too, sparing the newest six; past that the next request would fail with a context-window error, which is `LLM_ERROR`, which skips verify, so the work would never be scored. Earlier edits **persist** between attempts (nothing resets the tree; only the end of the task rewinds, to the last scored commit). An attempt whose tree is identical to the last scored one is not scored again.

**Stop reasons** (`agent_stop_reason`, eight values behind a CHECK constraint): `submitted`, `step_cap`, `budget_usd`, `budget_calls`, `budget_wall`, `llm_error`, `no_change`, `max_attempts`. `max_attempts` was added after review: without it "submitted clean" and "gave up after three red attempts" were one bucket in the report. It is set when every attempt was used and the last scored one still had visible regressions or collection errors; a clean last attempt keeps the agent's own reason. After a budget or LLM stop verify is **skipped**: the loop was cut short, so the tree may be half-edited.

**Models.** The `agent` stage routes to `claude-sonnet-5-5` (the headline model, `gateway/models.toml`); its `[price]` table is set explicitly in `gateway/models.toml` (LiteLLM's price map has no `claude-sonnet-5-5`; `cache_write` is the 5-minute rate, because the gateway sends `cache_control` without a ttl). The gateway still refuses any unpriced model (`UnpricedModelError`) rather than record a call as free, and rates are never guessed: a wrong price is a wrong benchmark. Comparison columns are one run each of an OpenAI and a Gemini model, declared as `comparison-a`/`comparison-b` placeholders in the same file and selected per sweep with `GATEWAY_STAGE_MODELS='{"agent": "<key>"}'` (`repolace-eval run --model <key>` sets it). The provider must be one of `anthropic`, `openai`, `gemini`, `minimax`, `vertex_ai` or `bedrock`, and `litellm_model` must start with `<provider>/`, checked at load, so one vendor's key is never sent to another vendor's API. **`bedrock` authenticates through an AWS profile, not a key:** `GATEWAY_AWS_PROFILE` and `GATEWAY_AWS_REGION` name it (boto3 resolves the credentials, so a short-lived `aws login`/SSO session works and nothing long-lived sits in `.env`; the `GATEWAY_` prefix is what lets them through the eval runner's environment allowlist). The credential kwargs are never stored in `llm_calls.request` and a caller cannot override them. `claude-sonnet-5-5-bedrock` is the same model through the `global.` inference profile, priced from AWS's rate card for the model's Marketplace offer (Standard, Global: the same rates as the direct API; the regional profiles are about 10% higher, so that entry must not be reused for a `us.`/`eu.`/`in.` profile). It is a separate model in the report: never mix it with the direct-API model in one sweep. A new AWS account has Anthropic quota 0 and no model authorization until the model-access form is filed and the Marketplace agreement is accepted. **`vertex_ai` is Gemini on Google Vertex AI with a Vertex API key** (`GOOGLE_API_KEY`), called by `repolace_gateway/vertex.py` over httpx REST, not through LiteLLM: LiteLLM's `vertex_ai/` route needs OAuth credentials and its `gemini/` route is AI Studio. `LLMClient` dispatches on the model's provider (an injected `acompletion` still serves every model, which is how tests drive it). The endpoint is fixed in code (`api_base` stays a reserved kwarg), the key is a query parameter, and every httpx failure is re-raised from the exception *type* only, so the URL and key never reach a log or `llm_calls.error`. Thinking tokens are added to the output count. A Gemini 3 `thoughtSignature` must be echoed with its function call, and the gateway's assistant message has nowhere to carry it, so it is packed into the tool call id (`call_<n>~<signature>`); the mocked tests cannot show Google accepts that, only `gateway/tests/test_gateway_vertex_live.py` can. Prices are in `models.toml` from AI Studio's page (Vertex's own was unreadable) and `gemini-3.8-flash` changes on 2027-01-01.

### Conflict resolver (decided; module built, not yet wired)

`agents/repolace_agents/resolver.py` is the agent that edits conflicted files when the target branch moved while a task ran (the merge primitives are in `shared/repolace_shared/git/`). It is **not a rerun of the Editor** and it does not share the main agent's graph, prompt or state: it is a self-contained bounded tool loop (`resolve_conflicts(ResolverDeps) -> ResolverResult`) that imports only public helpers, so the main agent's role split can change without touching it. The pipeline wiring (detect, `merge_no_commit`, refuse non-plain-text conflicts, call the resolver, `commit_resolution`) is the next item; nothing calls it yet.

- **Tools: exactly five** (`read_file`, `grep`, `list_dir`, `edit_file`, `submit_resolution`), built straight into a `ToolBox`. **No `run_python` and no `run_tests`**: both checkpoint-commit the tree before handing it to the sandbox, and a tree mid-merge is full of conflict markers, so the checkpoint would commit them (and the export refuses a tree that differs from HEAD). No `create_file` and no `search_code`. `edit_file` is the real tool wrapped so it is **also confined to the conflicted paths**, so "touch only the conflicted files" is enforced by code, and every other guard (`confine`, `.git*`, dotfiles, CI files, `ctx.is_protected`, size caps) is the main agent's. A conflicted path that is itself protected ends the run at once as `PROTECTED_PATH`, before any model call.
- **It never touches git or commits.** It edits files and calls `submit_resolution`. The host re-checks through `ResolverDeps.check(paths) -> problems` (no markers, no unmerged entries) and the host stages and commits via `commit_resolution`. The model's own claim of being finished is never the evidence.
- **Bounds:** 20 steps in total, 3 rounds (a round ends at `submit_resolution`; remaining problems go back as one message in a `feedback` block and another round), at most 8 tool calls executed per reply, a 400,000-character transcript cap with elision, malformed tool arguments replayed as `{}`. Two replies in a row with no tool call is `GAVE_UP`. Cost, call and wall-clock limits are the gateway's `TaskBudget` in the surrounding `task_scope` (the caller should give it a budget of its own); `BudgetExceeded` and `LLMCallError` become `BUDGET` and `LLM_ERROR`, everything else propagates. `ResolverStop` has seven values: `RESOLVED`, `GAVE_UP`, `ROUNDS_EXHAUSTED`, `STEP_CAP`, `BUDGET`, `LLM_ERROR`, `PROTECTED_PATH`.
- **Untrusted text:** the conflicted file contents (`output` family), the issue (`issue`) and the host's problem list (`feedback`) are framed with the existing nonce-delimited families only, and the system prompt is a pure function of `(limits, nonce)`. The summary is sanitised like `submit.summary`.
- **Model route:** the `resolve` stage, which is **optional** (`OPTIONAL_STAGE_FALLBACKS`) and **deliberately absent from the shipped `gateway/models.toml`**: it routes to the `agent` stage at `route()` time, so a per-run `GATEWAY_STAGE_MODELS` override of `agent` (what `repolace-eval run --model` sets) reaches the resolver and a sweep never mixes two models. A custom config may define `[stages.resolve]` to win, and `{"resolve": "<model>"}` is an accepted override. **The CLI and worker preflight must cover both `agent` and `resolve`** (an unpriced model is exit code 2 before any task is claimed); that belongs with the wiring item, not here.
