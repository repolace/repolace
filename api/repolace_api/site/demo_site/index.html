Replay of a recorded run

One real run, replayed

repolace is an agent that takes a GitHub issue, finds the code, writes a fix, runs the repository's tests in a locked-down sandbox and opens a pull request. This page replays one run of it from the data it recorded: the issue it was given, what it did and in what order, the tests before and after, the change it made, and what it cost. Nothing on this page runs anything; it only displays the recording.

Read this first

This is one run on a toy repository that was built to show the flow. It is not a success rate. The measured rate is on the benchmark page: 29 of 54 on 18 real SWE-bench Verified issues, with its caveats.

The replay on this page is the first attempt at this issue, and nothing was re-run or picked from several tries to make it. The video further down is made of screenshots of the real app showing this same run, taken after it had finished; it is not a live screen recording. After that first attempt the issue was run a second time, for a screen recording this page used to show. That run has its own pull request and its own cost, listed beside the video, and there was no third run.

The pull request text produced by repolace says “the repository had no failing test for this issue”. That sentence is wrong for this run: the repository did have a failing test, and it went from failing to passing, as the numbers below show. It is a fixed template line that ignores a baseline failure turning green, and it is recorded as a known defect.

repolace’s own scorer calls the result “passed (uncurated)”: it can see that a failing test turned green and nothing regressed, but it cannot know that test was written for this issue, so that is not proof the issue is fixed; here the issue’s example output was also checked by hand (see below).

    What this is and is not

    This is

    • A real run, replayed from the rows repolace wrote while it ran.
    • A way to see the whole path from issue to pull request, end to end, on a repository small enough to read.
    • A real pull request you can open on GitHub.

    This is not

    • A success rate or a benchmark result: it is a single run on a toy repository.
    • A live demo: you cannot start a task from this page, and nothing here talks to a model.
    • Proof that the fix is complete: the scorer cannot tell whether the failing test was written for this issue.
    • A picture of the hard cases: the repository is tiny and the bug is a one-function change.
